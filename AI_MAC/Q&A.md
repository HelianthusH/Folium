## 一、总体设计

按已确认的工况设计：**模块拼装，单次充电连续录音 48 小时，其中每天 2 小时同时进行蓝牙实时听写**。以下价格是物料估算，续航、识别延迟和三款工具的兼容性均为样机验收目标。本次交付为实施规格，固件、制板文件和实测报告列入后续产物。

| 模块         | 职责与数据流                                                 |
| ------------ | ------------------------------------------------------------ |
| 采集与控制   | XIAO nRF52840 **Sense** 的板载数字麦克风 → 双缓冲采样 → 编码队列。物理按键和电脑命令共用同一状态机。 |

**状态机**采用 `空闲 → 启动中 → 采集中 → 停止中 → 已停止`，已停止可再次启动。启动时先确认麦克风、卡和可用空间，再亮录音灯。停止时排空队列、封存末段、写入索引，然后熄灯。故障进入 `错误` 并保留原因。状态变化写入带递增序号和 CRC 的双份记录。意外断电后先修复末段，再按断电前的录音意图续录，并标记断电间隔。录音中按听写键只增加语音传输；空闲时按听写键创建短会话，松开后保存。

## 二、接口契约

USB 使用 CDC 串口，蓝牙使用自定义 GATT 服务，提供控制、状态通知和音频通知。两种连接共用协议版本、请求编号、会话编号和错误码。首次 USB 绑定需按设备键确认，蓝牙只允许已绑定电脑建立加密连接。Windows 助手通过仅当前用户可访问的命名管道向脚本开放同一组操作。

| ----------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `record.start` / `record.stop`      | `request_id`、音频配置或待停止的 `session_id`                | `session_id`、当前状态、开始或结束时间。重复请求返回原结果。 |
| `device.status` / `device.set_time` | 设备 ID；校时另传 UTC 时间                                   | 状态、电量、剩余空间、活动会话、时钟可信度、最近错误         |

**三个适配器的调用流程**为打开目标对话 → 绑定输入位置 → 按听写键 → 看实时字幕 → 定稿插入光标处。WorkBuddy 和 Codex 使用 Windows 辅助功能识别前台应用及编辑框。Claude Code 提供专用启动脚本，通过 Windows 伪控制台绑定实际运行的 Claude 进程。三个适配器均复用用户已登录的会话，无须智能体 API 密钥。切换窗口、关闭会话或定位失败时，定稿保存在助手中供手动粘贴。相同语句编号只插入一次。[WorkBuddy](https://www.codebuddy.cn/work/) · [Codex Windows 文档](https://developers.openai.com/codex/windows/) · [Claude Code 交互模式](https://code.claude.com/docs/en/interactive-mode)

| ----------------------------------- | ------------------------------------------------------------ |
| `MIC_DENIED` / `DEVICE_UNAVAILABLE` | Windows 可选麦克风输入被拒时显示授权入口。使用硬件拾音器只需 USB 或蓝牙访问。板载麦克风初始化失败时显示设备错误，修复后可重新启动。 |
| `NO_SPACE` / `WRITE_FAILED`         | 先执行留存规则允许的清理。仍无空间或写入失败时封存已确认数据，亮故障灯，记录最后有效采样位置。 |

### 音频、索引与导出

- **默认录音**采用 16 kHz、单声道、16 位采集，保存为 WAV 容器内的 IMA ADPCM。按 256 字节、505 个采样点一块计算，约 **29.2 MB/小时、1.40 GB/48 小时**。连续保存静音，关闭自动删静音。ADPCM 有损，需要逐采样保真时可切换 PCM16，约 **5.53 GB/48 小时**。两种模式都能放入 16 GB 卡。
- **目录和元数据**采用 `/REC/YYYY/MM/DD/<session_id>/<四位段号>.wav`，每 5 分钟切段。会话清单记录设备与固件版本、UTC 时间、时钟可信度、编码、采样率、样本数、缺口、字节数、SHA-256 和结束原因。设备维护按日期、会话可重建的索引；Windows 导入 SQLite，支持按本地时间范围和会话检索。时钟失效时保存到 `UNSYNCED`，保留会话和采样顺序。
- **留存与恢复**以段结束时间计算，保护最近 48 小时、正在写入和正在导出的段。剩余空间低于 512 MiB 时，从最旧的已封存且超过保护期的段开始清理。时间不可信时暂停按日期删除。写入期间每秒同步完整编码块和恢复记录，启动时校验临时文件，修复 WAV 长度并登记缺口。
- **导出**支持 USB 导出以及停录后取卡导入。按时间或会话选段，复制到临时目录，对照设备清单复算字节数和 SHA-256，通过后生成正式目录和校验报告。录音中可导出已封存的段。
